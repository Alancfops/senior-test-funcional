# Conventional Commits (English)

Gera mensagens e executa commits **somente quando o usuário pedir**. Todo texto do commit em **inglês**. Seguir [Conventional Commits 1.0.0](https://www.conventionalcommits.org/en/v1.0.0/).

## Formato

```
<type>(<scope>): <subject>

[optional body — English, wrapped ~72 chars]

[optional footer(s)]
```

| Parte | Regra |
|-------|--------|
| **type** | Obrigatório — ver tabela abaixo |
| **scope** | Opcional — módulo/área (`api`, `auth`, `docs`, `frontend`, …) |
| **subject** | Imperativo, minúsculas, sem ponto final, ≤ ~72 chars |
| **body** | Por quê, não só o quê; inglês |
| **breaking** | `!` após type/scope **ou** footer `BREAKING CHANGE: …` |

### Types permitidos

| type | Quando |
|------|--------|
| `feat` | Nova funcionalidade (RF, endpoint, tela) |
| `fix` | Correção de bug |
| `docs` | Só documentação |
| `style` | Formatação, sem mudança de lógica |
| `refactor` | Refatoração sem feat/fix |
| `perf` | Performance |
| `test` | Testes |
| `build` | Build, deps, tooling |
| `ci` | CI/CD |
| `chore` | Manutenção (gitignore, configs menores) |
| `revert` | Revert de commit anterior |

### Scopes sugeridos (projeto)

`api`, `auth`, `patients`, `assessments`, `instruments`, `pdf`, `contracts`, `frontend`, `docs`, `cursor`, `lgpd`, `deps`, `repo`

Use o scope mais específico; omita se não couber.

### Exemplos

```
feat(api): add patient list endpoint with therapist scope
fix(frontend): redirect to login on 401 responses
docs: align assessment flow with RF010 requirements
feat(auth)!: require Argon2id for password hashing

BREAKING CHANGE: legacy bcrypt hashes must be reset
chore(cursor): add figma-to-frontend skill
```

Detalhes e anti-padrões: [reference.md](reference.md).

## Fluxo ao commitar

1. `rtk git status` e `rtk git diff` (staged + unstaged).
2. `rtk git log -5 --oneline` — alinhar tom do repo.
3. Escolher **type**, **scope** e **subject** em inglês.
4. Mostrar mensagem proposta ao usuário se o pedido for só mensagem; se pediu commit, executar.
5. **Nunca** commitar `.env`, chaves, `session/*.md` ou segredos.
6. Após commit: `rtk git status` para confirmar.

### Comando

```bash
rtk git add <paths>
rtk git commit -m "$(cat <<'EOF'
feat(scope): short imperative summary

Optional body in English explaining why.
EOF
)"
```

Hooks devem rodar — **não** usar `--no-verify` salvo pedido explícito.

## Proibido na mensagem de commit

- ❌ Português no subject/body/footer
- ❌ `Co-authored-by: Cursor` ou qualquer co-autoria de IA/assistente
- ❌ `Signed-off-by` / trailers que indiquem que o agente fez o commit
- ❌ Frases como "Generated by AI", "Committed by Cursor", emojis de bot
- ❌ Alterar `git config` (user.name / user.email) — o commit usa **só** a identidade já configurada do usuário
- ❌ Commit vazio ou sem relação com o diff
- ❌ `--amend` / force push salvo regras do usuário e condições de segurança

Mensagem limpa, impessoal, como commit humano de engenharia.

## Breaking changes

```
feat(api)!: rename finalize assessment response fields
```

ou corpo com:

```
BREAKING CHANGE: `classification` renamed to `interpretationLabel`
```

## Relação com outras skills

| Situação | Também considerar |
|----------|-------------------|
| Commit de UI | mensagem reflete comportamento, não só pixels |
| Dados sensíveis | rule LGPD — commit não substitui revisão |
| Docs em `docs/` | preferir `docs(scope):` ou `docs:` |
