> **Importante:** o levantamento de requisitos e a PRD são **documentos vivos**. Conteúdo, escopo e prioridades **podem mudar** conforme validação clínica, orientação acadêmica ou decisões de produto.

## Arquivos principais

| Documento | Descrição |
|-----------|-----------|
| [PRD.md](./PRD.md) | Documento de requisitos de produto: visão, escopo MVP, personas, fluxos, RFs consolidados, critérios de aceitação e roadmap |

Há também um arquivo **Word** espelhando parte do trabalho acadêmico (quando aplicável):

- `Levantamento de requisitos Sênior Teste Funcional .docx` — tratá-lo como cópia; a referência atual em texto simples deve ser este diretório (`.md` acima).

## Protocolos clínicos (anexo técnico)

Instruções e referências bibliográficas por instrumento ficam em:

- **[testes/tug/](testes/tug/)** — TUG  
- **[testes/katz/](testes/katz/)** — Katz  
- **[testes/berg/](testes/berg/)** — Berg  
- **[testes/tinetti/](testes/tinetti/)** — Tinetti  
- **[testes/meem/](testes/meem/)** — MEEM  

Cada subpasta costuma ter um resumo (`*.md`) e o roteiro de aplicação (`avaliar.md`).

## Convenção de caminhos

Da raiz do repositório, use o prefixo `docs/` (por exemplo `docs/testes/meem/avaliar.md`).
